# 大硬精简发射器

[简体中文](README.md) | [英语](阅读我.英语.标记语言) | [法语](阅读我.法语.标记语言) | [俄语](阅读我.俄语.标记语言) | 微软式中文

这是一个 Minecraft（矿艺）发射器的存在，该发射器能够被运行在终端的内部当中。
它的书写方式，是通过 C井号（C#）以及终端站.图案使用者接口（Terminal.Gui）来被进行实现的；
它的收集方式，是通过本机代码提前编译（NativeAOT）的途径，向单个可执行文件的内部来被进行完成的。
对于点网络（.NET）运行时间的相关依赖，是不被包含在其中的；对于图案使用者接口的部分，
同样也是不被包含在其中的。

关于界面布置的部分，是向 [朴素手艺发射器2](https://吉特集线器.com/十六进制-龙/朴素手艺发射器2) 来被进行参考的；
关于联机部分的内容，是向 [你好矿艺发射器](https://吉特集线器.com/你好矿艺发射器-开发/你好矿艺发射器) 的陶瓦联机实现
来被进行参考的。

## 功能特性（Features）

**发射（Launch）**

- 对于游戏折叠器的部分，多个的存在状态是被包含的；对于编号名单的部分，
  会以数字片段作为依据，来被进行种类的处理
- 关于每一个编号的设定项目，其内容将会按照下列的方式来被进行提供：记忆的方式、
  爪哇、爪哇虚拟机器的争论、游戏相关的争论、窗户的尺寸、
  孤立的方式、发射之前的命令
- 对于那些处于缺失状态的图书馆文件，在发射之前，将会通过镜子的回退途径，
  被自动地进行使落下的处理；对于图书馆缺失的这种情况，将不再进行「拒绝出发」的
  相关处理
- 爪哇的部分，会在满足状况的最小主编号当中来被进行精选；对于 32 位爪哇的情况，
  记忆的容量将会被进行下降的处理，并且相关的通知也会被进行发出
- 游戏的过程，会通过 `DETACHED_PROCESS` 的方式来被进行出发；在终端的窗户被关闭的
  情况之下，游戏被连带结束的情况是不会被进行发生的
- 会议的相关记录，会向 `running-game.json` 来被进行书写；在发射器被关闭之后再次
  被开放的情况之下，仍然处于跑的状态的游戏是能够被进行察觉的
- 在坠毁之后的情况之下，会按照圆木的相关特征，来把过错以及建议，
  通过 14 条统治的方式来被进行给出
- 关于风俗主页的部分：预设、本地文本、远程统一资源定位符这三种方式是被包含的；
  对于 `${date}` `${player}` `${version}` 等等的代替符号，是能够被进行供养的

**使落下与任命（Download & Install）**

- 原版游戏的任命操作，其源泉是能够被进行切换的（官方、必姆西艾尔镜像应用编程接口
  （BMCLAPI）、自动）
- 装载机的任命操作：锻炉、新锻炉、织物、被子
- 社区资源的搜寻与任命操作：模组、模组包、数据包、资源的包装、阴影器；
  其中对于莫德林斯而言，击键是被免除的状态；对于诅咒锻炉而言，
  自备的击键是被需要的状态
- 关于使落下的部分，可简历的方式是被进行供养的：在网络失败的情况之下，`.tmp`
  将会被进行保留的处理，以用于下一次的延续用途；在检查总数失败的情况之下，
  则会被进行抛弃的处理
- 在模组被进行任命的时候，必选的依靠会被自动地进行使落下的处理
- 模组包的任命（`.mrpack`）：相对应的装载机会被自动地进行任命；藐视的部分，
  会被进行拔出的处理
- 编号的部分，会向 `.mrpack` 来被进行出口；在线匹配是能够被进行开放的，
  其用途在于体积的减小（被测量出来的结果：62 个模组的包，从 518 MB 向 186 MB 被进行了下降）

**编号的管理（Version Management）**

- 模组的管理部分：mods 折叠器的细看、批量的启用与禁用（向 `.disabled` 被进行再命名）、
  划掉、以及使现代化的支票操作
- 模组的使现代化支票：会按照罐子的安全散列算法1，在莫德林斯上来被进行最新
  编号的搜寻；一键使现代化的操作是能够被进行提供的
- 资源的包装、阴影器的管理部分：`options.txt` 以及 `optionsshaders.txt` 的内部，真实的启用状况
  会被进行阅读，并且会被进行书写
- 编号的补全：会按照编号的杰森，把委托人的罐子、图书馆、本机文件、
  资源文件，逐项地来被进行核对
- 编号的划掉操作（节省文件（存档）与构型会被连带地包含在其中）

**联机集线器门户（Multiplayer Portal Hub）**

- 陶瓦联机部分，会以被埋入的方式来被进行包含；房间的创造与加入操作，
  另外的使落下是不被需要的
- 公共中继小节的名单，会被自动地进行拉取的处理

**罐子的发射**

- 对于任意罐子的情况，独立的跑是能够被进行实施的（服务员、委托人、
  其他的爪哇节目单）
- 图案化的构型：记忆、垃圾收集器的预设（G1、ZGC、平行、串行）、
  额外的爪哇虚拟机器争论以及节目单的争论、服务员方式，这些内容是被包含的
- 命令投入框的部分，会向过程的标准投入，来把教导直接地
  进行寄出的处理
- 通过命令行的罐子小径传入方式，或者是把罐子向可执行文件上方进行拖和掉落
  操作的方式，该页面将会被直接地进行进入的处理

## 界面的门户（Portal of Interface）

页面的数量是六个，通过 F1 至 F6 的击键，来被进行切换的处理：

```
发射 | 使落下 | 联机 | 罐子 | 设定 | 更多
```

- **发射**：账目、编号名单、发射纽扣、主页功能区
- **使落下**：原版游戏、装载机、社区资源
- **联机**：房间的创造与加入
- **罐子**：独立罐子的发射
- **设定**：账目、爪哇、记忆、孤立、使落下的源泉、外观、表演
- **更多**：协助的导游、信用、微小的器具，
  以及百宝箱门户

## 运行的要求（Requirements）

- 窗户操作系统 10 以及以上的版本（过程的创造与窗户的列举操作，会通过温32应用编程接口
  来被进行使用）
- 游戏的发射操作，爪哇的自备是被需要的状态；或者在「设定 → Java」的位置，通过一键的方式来
  进行使落下的处理
- 终端的部分，100 柱子以上的尺寸是被推荐的状态；80 柱子是最小的限界，请务必对该限界
  予以遵守

## 建造（Building）

点网络 10 的软件开发工具包，以及微软视觉C加加工具链，在此是被需要的状态（该工具链会被本机代码
提前编译的链接器来使用）。

```bash
python scripts/build.py build      # 除虫建造：全部的自我考试入口都会被进行保留
python scripts/build.py publish    # 释放发布：产物会被放置在 bin/Release/net10.0/win-x64/publish/
```

`scripts/build.py` 会对三件事情来被进行处理：还原的跳过、MSYS 环境可变的的清理、
以及 `IlcUseEnvironmentalTools` 的加以（让本机代码提前编译的收集器，直接地对环境内部的工具链
来被进行使用，而不通过登记处来被进行视觉工作室的察觉）。

除虫建造的情况下，自我考试的入口是被包含的；释放建造的情况下，则是不被包含的：

```bash
LargeHardLiteLauncher.exe --uitest        # 六个页面的构造烟雾
LargeHardLiteLauncher.exe --selftest      # 31 段主张（在本机代码提前编译的产物上方，跑的操作是不被允许的）
LargeHardLiteLauncher.exe --vmtest        # 编号管理的航行
LargeHardLiteLauncher.exe --packcfgtest   # 资源的包装 / 阴影器构型的读取与书写
LargeHardLiteLauncher.exe --updatetest <编号折叠器的名称>   # 模组的使现代化支票
LargeHardLiteLauncher.exe --launchtest <编号折叠器的名称>   # 游戏的真发射，圆木的追踪会同步地进行
```

## 数据与构型（Data & Config）

```
%USERPROFILE%\.largehardlitelauncher\
  config.json         全局构型的门户
  logs\               发射器的圆木
  java\               通过发射器被进行使落下的爪哇
  terracotta\         被拔出的联机核仁，集线器的所在位置
  cache\              主页的储藏处
  running-game.json   当前正在跑的游戏记录
```

游戏的文件以及编号，仍然会被放置在 `.minecraft` 折叠器的内部；搬家的操作是不会被进行发生的。

## 已知的限制（Known Limitations）

- 对于窗户操作系统是独有的状态；十字站台的计划是不被包含的（过程的创造与窗户的
  察觉，会通过温32 来被进行依靠）
- 模组的使现代化支票，是莫德林斯独有的状态；诅咒锻炉的指纹应用编程接口，击键是被需要
  的状态，并且速率的限制也是比较严厉的状态
- 发射器自身的使现代化支票是不被包含的；编号的更换，需要手动的可执行文件代替操作
- 例子的单个运行方式；对于第二个例子的情况，仅仅会进行通知的弹出而已
- 模组包的进口，是 `.mrpack` 独有的状态；对于诅咒锻炉的拉链模组包，供养是不被进行
  提供的

## 常见被问的问题（FAQ）

**为什么会被作成终端界面的形式？**

矿艺发射器的时间，在被花掉最多的位置是使落下、拔出、拼争论这几处；而界面部分，仅仅是
把上述的这些结果来进行展览的责任而已。在窗户数量比较多的情况之下，每英寸点数的缩放、
深色命题、高对比度、无障碍读屏、圣洗池的回退，全部都会被连带地进行处理的必要
是存在的；终端的情况下，这一层会被进行归零的处理，并且通过 ssh 的远程使用体验
也是能够被进行供养的。

**为什么是 24 MB，而朴素手艺发射器只有 5 MB？**

口径并不是同一个状态。朴素手艺发射器会依靠系统内部被进行任命的点网络桌面运行时间（数百 MB），自身仅仅
带有业务的法规而已。本项目的自足的状态，运行时间的全部都会被包含在
其内部；另外还有 7.75 MB 是被埋入的联机核仁。在此以同等的口径来被进行计算的情况之下，
本项目的业务法规本体为 158 KB 的状态。

**存档会被进行划掉的处理吗？**

不会被进行。会进行文件划掉的容貌，是「编号的划掉」所独有的部分；在点之前，对白的
确认会被弹出，在对白的内部，「此操作撤销不被予以」的内容会被明确地进行书写。模组的「禁用」
仅仅是改名的操作而已；资源的包装与阴影器的「禁用」，仅仅会对 `options.txt` 内部的一行构型
进行修改而已。
